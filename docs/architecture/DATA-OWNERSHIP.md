# Data ownership and consistency

Domains own behavior and identifiers. Atlas.Infrastructure SQL repository adapters translate domain objects to persistence rows; Atlas.Persistence owns the shared EF model and migrations.

| Data | Authority / ID generation | SQL Server tables |
|---|---|---|
| Nodes | Graph | NodeRows |
| Node types / requested types | Graph | NodeTypeRows / NodeRequestedTypes |
| Parent relationships | Graph, on child Node | NodeParents |
| Curated reactions / node associations | Graph | ReactionDefinitionRows / NodeReactionRows |
| Reaction audit entries | Graph lifecycle history | ReactionAuditEntries |
| Documents / ordered block references | Content | DocumentRows / DocumentBlocks |
| Typed block payloads | Content | BlockRows |
| Participant profiles | Participants | ParticipantRows |
| Credentials, tokens, global roles | ASP.NET Core Identity; account Id equals ParticipantId | identity.Users / Roles / UserRoles / UserClaims / RoleClaims / UserLogins / UserTokens |
| Current votes | Voting | VoteRows |
| Communities / membership / node associations | Communities | CommunityRows / CommunityMembershipRows / CommunityNodeRows |
| Threaded comments | Comments | CommentRows |
| Reports and moderation decisions | Moderation | ModerationCaseRows |
| Notifications / delivery attempts | Notifications | NotificationRows / NotificationDeliveryAttempts |
| Recipient preferences | Notifications | NotificationPreferencesRows |
| Integration-event payloads | Contracts shapes; producer supplies values | Dispatched in memory; no durable event table |
| Vote summaries / Discovery results | Voting / Discovery derived reads | Computed from current records |

## Integrity rules

- Aggregate GUIDs are generated by Atlas, not SQL Server. Association keys use ID pairs; ordered child keys use owner ID plus Position.
- Foreign IDs remain references rather than ownership of another domain object.
- Configured foreign keys enforce existing referenced records. Nullable FKs allow absence, but non-null IDs must resolve.
- Owned child rows cascade on physical owner deletion. Independent references use NoAction; deletion requires explicit resolution of dependents.
- A unique vote index enforces (ParticipantId, TargetType, TargetId).
- A unique notification index enforces (OccurrenceId, RecipientParticipantId); preferences use ParticipantId as the primary key.
- Community Name is unique under its SQL collation; memberships and node associations use composite primary keys.
- Polymorphic vote/comment/notification targets, poll/chart references, occurrence IDs, and opaque type-owner strings require application validation.

## Transaction boundaries

[SqlRepository](../../src/Atlas.Infrastructure/Storage/SqlRepository.cs) starts a transaction for a standalone save or joins the current operation. Replaced owned children are removed and flushed before new rows with the same keys are attached. Node metadata saves preserve stored parents instead of replacing them.

The following workflows explicitly share one context and SQL transaction:

- Node creation: block, document and Node, including an optional parent.
- Community creation: community and owner membership.
- Reaction replacement: new association and old association supersession/audit.
- Moderation: grouped decisions, review requests and restoration.
- Content block addition: payload and document composition.

A failure rolls back their earlier writes. This guarantee comes from the operation boundary, not merely from sharing a database. Independent saves outside a boundary remain separate transactions. See [implementation and failure evidence](../security/validation/IMPLEMENTATION.md#workflows-and-evidence).

- Serializable transactions and SQL constraints protect competing writes; expected deadlock/constraint failures become [OperationConflictException](../../src/Atlas.Contracts/Operations/OperationBoundary.cs). Callers reload before retrying; no automatic successful upsert is implied.
- Node creation and parent changes request the shared graph application lock before ancestry checks. Metadata edits do not request it. Ordinary SQL row/range blocking remains possible.
- There is no universal rowversion/stale-edit policy; some relationship operations check current state. Rollback does not rewind objects in caller memory.

## Event consistency

The host dispatches recorded facts after saves. SQL commits and in-memory event dispatch are not atomic. Notification deduplication prevents duplicate rows for an occurrence/recipient; it does not guarantee external side effects exactly once.

For setup and migration commands see [SQL Server persistence](../PTT-87-SQL-Server.md). For behavior and boundary gaps see the [context map](CONTEXT-MAP.md).

## Account/profile consistency

[Identity registration](IDENTITY.md#registration-transaction) is an explicit cross-boundary transaction on the shared context: profile, credentials, and Member assignment commit together. This does not make unrelated Atlas multi-save workflows atomic. The developer-generated Identity migration is committed in PTT-94.
