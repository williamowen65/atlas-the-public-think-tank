# First backend coverage report

This pilot runs Atlas.Graph.Tests without SQL or the API. It measures only the
Atlas.Graph and Atlas.Contracts assemblies available to that test run.
It is not whole-backend, frontend or SRS coverage.

## Windows

Pull PTT-152-test-consistency. From the repository root:

```powershell
powershell -NoProfile -File tests/Invoke-GraphCoverage.ps1
```

PowerShell 7 also works with `pwsh -File tests/Invoke-GraphCoverage.ps1`.
If local script policy blocks execution, use the equivalent manual commands
below rather than changing machine policy.

The script restores repository-pinned tools/packages, builds and runs tests with
coverage, then prints the exact report and result paths. Each run gets a new
directory under ignored artifacts/test-reports; previous reports are preserved.

Open the printed html/index.html in your browser. It shows measured source lines,
branches and uncovered code. Open the printed graph.trx in Visual Studio for test
results. TRX is test-run XML generated by VSTest; do not write it yourself.

Read the test result counts separately from coverage percentages. A failing run
may still produce coverage; the script preserves its failure exit code. Missing
coverage is reported as a collection error, not as 0% or success.

## Manual equivalent

Use a fresh results/target directory per run to avoid merging stale evidence:

```powershell
dotnet tool restore
dotnet test tests/Atlas.Graph.Tests/Atlas.Graph.Tests.csproj --configuration Release --settings tests/graph-coverage.runsettings --collect:"XPlat Code Coverage" --logger "trx;LogFileName=graph.trx" --results-directory artifacts/test-reports/manual-graph/results
dotnet tool run reportgenerator "-reports:artifacts/test-reports/manual-graph/results/**/coverage.cobertura.xml" "-targetdir:artifacts/test-reports/manual-graph/html" "-reporttypes:Html;Cobertura;TextSummary"
```

Check the test exit status before running the report command; HTML generation
does not turn failed tests into passing tests.

## What changed

- The Graph test project references Coverlet collector and explicitly uses VSTest
  support rather than native MTP dotnet-test integration.
- ReportGenerator is pinned in .config/dotnet-tools.json; no global installation.
- The runsettings scope includes Graph and Contracts, excluding test assembly and
  obj-generated files. Other application projects are unmeasured, not 100% covered.
- The script saves test outcomes, coverage data and commit/environment metadata.
- No coverage threshold has been added.

## Verification status and next steps

The editing environment has no dotnet runtime, so package restore, compilation
and actual collection need verification in CI and on Windows. Do not quote a
baseline percentage until the first report is inspected. Confirm source links,
line/branch data, test counts, and that no tests were unexpectedly skipped.
Frontend reporting, SQL coverage aggregation and requirements traceability remain
separate later steps in the reporting plan.
